ADR-0001：CesiumEntity 使用类型化 config 对象 ​

状态 ​

已接受

背景 ​

原 API 将 position、point、label、polyline 和 polygon 全部平铺为组件属性，难以判断参数属于点、线还是面，也无法表达线和面标签需要独立位置。

决策 ​

新增由 type 区分的 CesiumEntityConfig，通过 <CesiumEntity :config="config" /> 传入。点和线直接使用自身坐标渲染，只对没有标签坐标的面计算中心；placement 用于设置标签偏向，也允许通过 position 覆盖自动位置。旧平铺属性继续兼容，新文档优先介绍 config。

业务配置中的颜色同时接受 CSS 字符串和 Cesium Color，标签绘制方式同时接受 fill、outline、fill-and-outline 和 Cesium LabelStyle，由组件在创建 Entity 前统一转换。

其它常用 Cesium 值同样在组件边界转换：alwaysVisible、数组形式的 pixelOffset、字符串形式的贴地与对齐方式，以及经纬度坐标数组。Cesium 原生对象只作为高级兼容输入，不作为主要文档写法。

影响 ​

正面 ​

  • 一个实体的图形、标签和业务数据集中管理。
  • TypeScript 根据 type 提示正确配置，并检查线面标签位置。
  • 旧项目可以无修改升级。

负面 ​

  • 组件内部需要保留一层新旧 API 归一化逻辑。
  • 在下一个主版本移除旧 API 前，两种写法会同时存在。

备选方案 ​

  • 直接删除旧 Props：API 最简洁，但会破坏现有项目。
  • 继续使用平铺 Props：实现成本最低，但无法解决文档和类型语义模糊的问题。
